# Chronicles of Azeroth

World of Warcraft addon for the WoW Forever client (interface 16001): a completionist tracker of
quests by zone and of profession recipes, per character or for the whole account. The addon
lives in `ChroniquesAzeroth/`, its data is generated by `tools/`, and `tests/` checks it offline.
[CONTRIBUTING.md](CONTRIBUTING.md) sets the conventions every change follows, including the
language of the repository.

## Runtime principles

- The addon depends on the WoW client alone. It reads no other addon and makes no network
  access; what the client cannot provide is generated at build time and shipped in `Data/`.
- Text about game content (quests, items, spells, zones, factions) is asked from the client at
  runtime, so that it is the official wording in the player's language. A text is shipped only
  when no client API exposes it, or when the client depends on a server that may not answer;
  the shipped text then exists for every supported language.
- Nothing is made up: a reward, a source or a learned state is shown only when the client or
  the data states it, and an unknown value is shown as unknown.
- The code is Lua 5.1, the language version of the WoW client.

## The Forever client

The Forever client runs the modern engine but does not expose every retail API, and some
functions keep their legacy names. Code never calls an uncertain API directly: `Core/Compat.lua`
wraps each one with its alternatives, and `Core/Diagnostics.lua` logs at login which of them
exist; a new client API is added to both. Masks that may exceed 32 bits (race masks include bits
32 and 33) are tested arithmetically with `ns.HasBit` and `ns.MasksIntersect`, never with the
client's 32-bit `bit` library.

## Architecture

- The TOC lists the files in load order and carries the version, which the addon reads from it.
  The files share the private table the client passes to each of them (`local _, ns = ...`).
- `Core/` holds the services: the lifecycle, events and messages (`Init.lua`), the log, the
  client wrappers, the saved variables, the player and the client texts (`Names.lua`).
  `Modules/` holds the progress logic of each domain, independent of the interface, and
  notifies it through messages (`CA_PROGRESS_CHANGED`, `CA_NAMES_UPDATED`...) rather than by
  calling it.
- `UI/Widgets.lua` provides every visual building block, in the look of Chronicles of Azeroth
  (the native tooltip panels, the golden borders, the medallion, the artwork of the zones), and
  the views of `UI/Views/` only assemble them, so that a visual change is made once. Every view
  lays its tab out on the page of `Views/Layout.lua`: the groups on the left, the selected group
  and item in the middle, the items of the group on the right. A tab appears when the TOC loads
  its view.
- Text sizes are written for the default size of the standard text of the game and set
  through `Theme.SetFont`, which scales them by the size the client gives that text, so that
  the window follows the text of the game.
- Event handlers, message handlers, list rows and view refreshes run through `ns:SafeCall`, so
  that one failure is logged with its traceback instead of breaking the window.

## Localization

English (`Locales/enUS.lua`) is the reference and the fallback; every other locale file holds
the same keys, which the tests verify. A key added for one language is added for all of them in
the same change. French follows the official French terms of the game, and its typography: a
no-break space before `:`, `;`, `!` and `?`.

## Saved variables and logs

The saved variables belong to the players: a change of their layout migrates the existing data
(`Core/Database.lua`) instead of discarding it. The log is kept in `ChroniquesAzerothDB.log`,
which the game writes on `/reload` and on logout, in
`WTF/Account/<account>/SavedVariables/ChroniquesAzeroth.lua`: reading it is the way to
investigate a problem met in the game, so new behaviour that can fail logs enough context to be
diagnosed from the log alone.

## Generated data

The files of `ChroniquesAzeroth/Data/` are produced by `python -I tools/build_data.py` and are
never edited by hand: a correction belongs in the generator, or upstream in QuestieDB. The
generator reads QuestieDB through `tools/questie_dump.lua`, which needs PUC Lua 5.1 (LuaJIT
rejects the size of QuestieDB's tables), and the client tables of the build given by `--build`;
`--offline` rebuilds from the cache alone. The quest row layout and flags are shared between
`tools/build_data.py` and `Core/Constants.lua`, which change together. `ChroniquesAzeroth/Assets/`
holds the TGA artwork, rebuilt by `tools/import_zone_art.py`; an artwork added since the original
manifest is listed in `tools/zone_art.csv` with its source and the band of the image that shows
its subject.

## Checks

```sh
lua5.1 tests/run.lua
CA_TEST_LOCALE=frFR lua5.1 tests/run.lua
bash tools/check_version.sh
```

The tests load the addon in TOC order over `tests/wow_stub.lua`, log in, open the window and go
through every tab. The stub accepts only real widget methods, so it catches calls the game would
reject: a widget method or client API newly used by the addon is added to the stub, after
checking that it exists in the client. Any logged error or missing translation fails the run.
The game itself cannot be launched from here: in-game checks are done by the user, then read
back from the log.
