# Chronicles of Azeroth

World of Warcraft addon for the WoW Forever client (interface 16001): it tracks the completion
of quests by zone and of profession recipes, per character or for the whole account. The addon
lives in `ChroniquesAzeroth/`, its catalogues are generated by `tools/`, and `tests/` checks it
offline. [CONTRIBUTING.md](CONTRIBUTING.md) sets the conventions every change follows,
including the language of the repository.

## Runtime principles

- The addon depends on the WoW client alone. It reads no other addon and makes no network
  access; the data the client cannot provide is generated at build time and shipped in the
  catalogue files.
- The Forever client mixes Classic and recent APIs depending on the build. An API is called
  only after checking that it exists (`type(...) == "function"`), and through `pcall` when it
  may fail, so that a missing API degrades a feature instead of breaking the addon.
- Login stays light: recipes are read from the native profession window only once the
  player opens it, and long walks over the catalogue are spread over several frames.
- Nothing is made up: a quest reward, a recipe source or a learned state is shown only when
  the client or the catalogue states it, and an unknown value is shown as unknown.
- The language of the client decides the language of the interface: `frFR` gets French,
  every other client gets English. Every text shown in game has both entries in the
  localization tables.
- The code is Lua 5.1, the language version of the WoW client.

## Files

- `ChroniquesAzeroth/ChroniquesAzeroth.toc` lists the files in load order and carries the
  version, which must equal `CA.VERSION` in `Core.lua`.
- The files share the addon frame `CA` and the private table the client passes to every
  file (`local _, ns = ...`). Each file reaches what another one provides through `ns`, and
  since the TOC order is the load order, a file only uses at load time what an earlier file
  has set.
- `Core.lua` creates `CA` and holds the localized texts; `Zones.lua`, `Quests.lua` and
  `Professions.lua` hold the data and the tracking logic; `UI/` holds the window, one file
  per tab and the shared widgets; `Events.lua` wires the slash commands and the game events.
- Every tab that browses groups of items lays them out in the three columns of
  `ns.columns` (`UI/Widgets.lua`): the groups on the left, the selected group and item in
  the middle, the items of the group on the right. A new tab builds on these columns and
  on the other shared widgets, so that every tab looks and behaves alike.
- `ChroniquesAzeroth/QuestCatalog.lua` and `ChroniquesAzeroth/ProfessionCatalog.lua` are
  generated: they change only by running their generator in `tools/`, never by hand.
- `ChroniquesAzeroth/Assets/` holds the TGA artwork, rebuilt by `tools/import_zone_art.py`.

## Checks

```sh
lua5.1 tests/run.lua
CA_TEST_LOCALE=frFR lua5.1 tests/run.lua
bash tools/check_version.sh
```

The tests run the addon on top of `tests/wow_stub.lua`, whose widgets accept only the methods
it lists: a widget method the addon starts to use is added to the stub, after checking that
it exists in the client.
